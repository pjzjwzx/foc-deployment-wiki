配置与验证参考

读完 00–02 章后，可以用本页核对 PWM、采样和启停依赖的配置。下表对应课程中的 STM32H743VIT6 示例。CubeMX 的器件项显示为 STM32H743VITx，具体接线以手中板卡为准。

示例配置

核对项 H743 示例
时钟 HSE 25 MHz，CPU 480 MHz，APB2 120 MHz，TIM1 计数时钟 240 MHz。ADC 内核时钟 36 MHz，FDCAN 内核时钟 48 MHz。
TIM1 三相 PWM 中心对齐模式 3，PSC=0，ARR=6000，RCR=0，PWM2，ARR 与 CCR 预装载。主输出 CH1/2/3 对应 PA8/PA9/PA10，互补输出对应 PB13/PB14/PB15。死区配置字段为 10，关闭 Automatic Output。计数往返一趟为 2 × 6000 ÷ 240 MHz = 50 μs，对应 20 kHz。
ADC 注入组 TIM1 CH4 设为内部 PWM1，比较值 1，以 OC4REF 作为 TRGO。三路 ADC 在其下降沿触发，每个载波采集一组三相电流。ADC1 IN5/PB1、ADC2 IN7/PA7、ADC3 IN0/PC2_C，各用一个 Rank。14 位，采样 2.5 个 ADC 时钟周期，注入组过采样 16 次、右移 2 位。
ADC 规则组 ADC1 IN8/PC5 测母线电压，规则组由软件启动，采样 64.5 个 ADC 时钟周期。LAB1 使用名义母线算观察波形，LAB2 的运行分支使用实测母线。
FDCAN1 Classic CAN、Normal、1 Mbps。48 MHz 时 Prescaler=3、Seg1=13、Seg2=2、SJW=1。使用标准 11 位标识符和 8 字节数据。PD0/PD1 是 MCU 端 RX/TX，适配器接板上收发器后的 CANH/CANL。
UART4 TX PB9、RX PB8，1 Mbps、8N1、无流控。发送使用 DMA。JustFloat 每帧六个浮点数，应用按 1 kHz 准备快照。LAB2 的 ch0–ch2 是相电流，ch3 是机械角，ch4 是反馈电角，ch5 是给定电角。
SWD 与驱动 SWDIO 为 PA13，SWCLK 为 PA14。示例板的驱动使能为 PD4，故障输入为 PD5。先确认 MCU 引脚有 PWM，再单独确认驱动使能。LAB1 的观察路径保持驱动关闭。

已另行取得示例工程时

从包含 .ioc、.project 和 .cproject 的工程根目录开始。CubeMX 打开 .ioc 逐项核对上表，CubeIDE 导入工程根目录。config/board_config.h 存板级比例和方向，config/motor_config.h 存电机参数和限值，config/lab_config.h 存实验阶段、节拍和超时。LAB1 对应 LAB_PWM_SVPWM，LAB2 对应 LAB_OPEN_LOOP。保存设置后重新构建，再核对 ELF 的路径和时间。

有配套构建脚本和 ARM GCC 时，也可在工程根目录单独构建 LAB2。下面的命令输出 build/lab2/FOC_Arclab_H743_V3.elf。

python tools/build.py --stage 2 --output build/lab2

只预览启停顺序时运行下面一条。它打印停机、申请 Open、持续给定、再次停机四步。按第 02 章确认板卡、空载、限流、状态回读和直接切断功率的条件后，再选择实际适配器和发送选项。

python tools/can_demo.py open --electrical-speed 10 --vq 0.2 --duration 2

换用其他 STM32

控制算法的接口是有单位的电流、角度和电压，以及 0 到 1 的三相占空比。保留这些约定，可以继续用同一组输入核对逆 Park 和 SVPWM。更换 MCU 或驱动板时，下面几项要按新硬件重新决定。

  • 定时器。 从目标定时器的实际时钟与计数模式推导载波和控制周期。核对互补输出、极性、死区、CCR 锁存时刻和驱动允许条件。中心对齐下，要区分完整载波周期与本拍比较值的提交截止。
  • 采样。 确定由哪个事件触发电流采样，何时取得完整的新样本，再安排控制计算。按放大倍数、分流电阻、ADC 基准与过采样方式重算 A/count，并在实板确认相序与极性。
  • 传感器与电机。 核对编码器分辨率、方向、时间戳和样本超时，重新确认极对数、电零点、减速比与限制值。电角与机械角在代码和模型中要使用同一套单位。
  • 接口与关断。 适配板级的 PWM 提交、驱动使能、故障输入和立即关断。同步修改 CAN/UART 速率、引脚和中断优先级。涉及 DMA 或标定保存时，按目标芯片核对缓冲区可达性、缓存与 Flash 预留。

验证记录

项目 目前的结果
构建与配置恢复 示例通过 13 次构建，覆盖七个实验阶段的默认电机 Release，以及三个电机配置在完整阶段的 Debug 和 Release。另已用 CubeIDE 完成导入和构建。CubeMX 再生成验证使用 6.16.1、数据库 6.0.150 与 STM32CubeH7 V1.12.1，恢复工程配置后成功重建。
电脑上的测试 算法、标定、协议和应用状态在模拟板级接口下通过测试。CAN 工具也覆盖了启停确认、故障退出等流程。有完整工程时可运行 python tools/check.py。
目标板 实板下载、转动、PWM 与采样时序、通信失联后的关断时间均待实测。记录时把编译结果、模拟结果和示波器或现场读数分开。

已知通信时序问题。 在电脑的应用测试中，若后台在 ADC 触发后、回调执行前接受有效 CAN 命令，回调可能用较早的触发参考时间减去较新的命令时间。无符号差值回绕会误报 CAN 超时（故障位 0x08）并关桥。这个顺序已用模拟板级接口复现，实板上是否遇到仍待验证。
